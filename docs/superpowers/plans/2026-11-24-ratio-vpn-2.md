# Ratio VPN 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ratio VPN 2.0: schnellerer Paketweg, Automatik-Regeln für beliebige Programme mit Ausfall-/Kick-/Doppel-IP-Logik, Statistik und eine komplett neue WPF-Oberfläche.

**Architecture:** Core (`RatioVPN.Core`, net8.0, plattformneutral testbar) bekommt Leistungsänderungen, das Regelmodell, AutoPilot v2, IP-Prüfplaner und StatsStore. Die App (`RatioVPN.App`, WPF) wird in Seiten (UserControls) und kleinere ViewModel-Dateien aufgeteilt und neu gestaltet; ein separates Vorschau-Werkzeug rendert die Seiten mit Demo-Daten als PNG. Bench-Projekt misst vorher/nachher.

**Tech Stack:** .NET 8, C# 12, WPF + WinForms (Tray), WinDivert 2.2 (unverändert), eigener Testläufer `tests/RatioVPN.Tests` (kein NuGet).

**Spec:** `docs/superpowers/specs/2026-11-24-ratio-vpn-2-design.md`

## Global Constraints

- Die laufende RatioVPN.exe (Downloads-Ordner, PID läuft als Admin) **nie** beenden, überschreiben oder eine zweite Instanz starten. Die neue App wird **nie** gestartet (sie würde die alte beenden). Kein WinDivert-Handle öffnen.
- Tests/Bench/Preview verwenden **nur** temporäre `SettingsStore`-/Stats-Pfade, nie `%APPDATA%\RatioVPN`.
- Keine neuen NuGet-Pakete in Core/App/Tests. Bench und Preview ebenfalls ohne NuGet.
- Einstellungen abwärtskompatibel: `AutoPilot`-Objekt inkl. `TitlePattern` bleibt; neue Felder nur ergänzen.
- UI-Texte Deutsch, du-Form, wie bisher. Version `2.0.0`.
- Build-Ausgabe der App: `publish-2.0/` (in `.gitignore` aufnehmen). Kein `git push`.
- Testlauf: `dotnet run --project tests/RatioVPN.Tests -c Release` → letzte Zeile `N bestanden, 0 fehlgeschlagen`.
- Commits auf Branch `automatik` (später umbenennen ist Sache des Nutzers).

## Review Focus

1. **Leck beim Umschalten der Umleitung:** Regel entsteht, während die Umleitung aus ist → Umleitung muss *vor* Rückkehr von `ApplyRules` laufen; Fehler beim Öffnen muss sichtbar werden (Banner), nicht verschluckt. → Test in Task 3.
2. **Alte Einstellungen:** `settings.json` ohne `AutoRules`, mit `AutoPilot.Enabled=false`, mit ungültigem `TitlePattern`, mit Fensterregel auf gelöschte Verbindung → Laden ohne Absturz, Migration genau einmal. → Tests in Task 5.
3. **Prozess endet/PID-Wiederverwendung:** Instanz verschwindet zwischen Scan und Zuordnung → `AssignWindow` ignoriert (StartTicks 0), keine Meldungsflut, Kick-Zähler werden aufgeräumt. → Test in Task 9.
4. **Alle Verbindungen gleichzeitig weg (Internet aus) und wieder da:** keine Wechsel, genau eine „Internet weg“- und eine „wieder da“-Meldung, danach normale Logik. → Test in Task 8.
5. **Ungültiges Regex im Regel-Editor / leere Regel (keine Exe, kein Titel):** wird nicht übernommen bzw. passt auf nichts, kein Absturz. → Tests in Task 7 (Editor zeigt den Fehler, Task 18 prüft per Preview).
